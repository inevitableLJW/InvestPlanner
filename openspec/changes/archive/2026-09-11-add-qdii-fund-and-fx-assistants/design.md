## Context

InvestPlanner 当前由 Go API、React Web 与 MySQL 组成，月度建议金额由服务端统一计算。系统没有基金行情、指数行情或汇率数据接入，也没有可靠的标的市场属性；仅凭标的中文名称推断 QDII、港股或美股会造成错误分类。

本变更同时涉及外部数据、计算、缓存、API 与月度记录页交互。外部公开数据会变化、限流或失效，且部分来源只代表特定销售渠道，因此任何市场数据都不能成为保存月度记录的硬依赖。

## Goals / Non-Goals

**Goals:**

- 只针对计划中真实存在且已配置市场属性的标的提供助手。
- 为 QDII 标的展示同指数基金的当前可执行信息，并在数据充分时计算可解释的跟踪误差。
- 按真实海外直投市场动态生成 USD/HKD 年度换汇需求，不产生无关币种。
- 所有外部数据保留提供方、观测时间、抓取时间、陈旧状态和失败原因。
- 上游失败时保持月度建议与记录流程可用，并统一显示 `--`。

**Non-Goals:**

- 不提供自动下单、自动申购、自动购汇或投资建议。
- 不把天天基金渠道限额解释为基金公司或所有销售渠道的统一限额。
- 不在本变更中接入券商账户、银行账户或用户真实持仓。
- 不根据生成式参考图新增计划标的，也不要求左侧列表固定为七个海外标的。

## Decisions

### 1. 使用显式市场档案，不根据名称推断

为每个可配置标的维护 `market_profile`：

- `execution_mode`: `local`、`qdii`、`direct_us`、`direct_hk`、`stock_connect`
- `settlement_currency`: `CNY`、`USD`、`HKD`
- `benchmark_id`: 精确基准标识，可为空
- `fx_quota_relevant`: 是否参与个人换汇规划

QDII 基金与基准映射另存为可审计配置，包含生效时间和维护人。系统 MUST 只使用精确映射；名称模糊匹配只能生成后台待确认候选，不能直接进入用户结果。

常用列表中的系统预设标的是受控产品配置，不属于名称推断：系统为每个预设名称维护固定市场档案，并在服务端保存时强制覆盖客户端值。预设标的页面不显示执行方式；只有列表外自定义标的允许用户选择。历史数据仅对这些已确认的预设名称做显式回填，其他名称继续保持 `unknown`。

**替代方案：**根据“美股”“港股”“纳斯达克”等名称判断。该方案无需迁移，但重命名、多语言和港股通场景都会误判，因此拒绝。

### 2. 通过内部 AKTools 服务隔离 Python 数据采集

Go API 定义稳定的领域接口，默认通过内网 HTTP 调用固定版本的 AKTools/AKShare 服务；该服务不暴露到宿主机公网。Tushare 与中国外汇交易中心均作为同一领域接口下的可选提供方。提供方响应先转换为内部 DTO，再写入快照表，前端不会看到上游原始字段。

首版基金数据流固定为：

1. 使用 `fund_purchase_em` 的完整目录发现人民币 QDII 场外候选，并补充天天基金渠道的申购状态、下一开放日、最低申购额与日累计限额；不得把候选数固定为某个常数。
2. 使用 `fund_etf_spot_em` 的完整行情目录发现可能的场内 ETF 候选并保存行情和 IOPV。
3. 对可能属于纳斯达克 100 或标普 500 的候选逐只读取 `fund_overview_em`。名称匹配只生成待核验候选；仅当“跟踪标的”规范化后严格等于受控白名单中的纳斯达克 100 或标准普尔 500 时，系统才自动建立带生效时间的精确映射。主动基金、纳斯达克科技/生物科技和标普 500 等权重等相近名称不得激活。
4. 使用 `fund_open_fund_info_em` 保存单位净值与累计净值原始口径。
5. 配置 Tushare 且 `fund_nav.adj_nav` 与兼容总回报基准均可用时，优先计算严格口径；普通单位净值或累计净值不能重命名为复权净值。
6. 严格口径不可用时，内部代理口径使用场外基金或场内 ETF 的累计净值，对比 QQQ/SPY 前复权收盘价与国家外汇管理局每日 USD/CNY 中间价合成的人民币序列。纳斯达克 100 映射到 QQQ，标普 500 映射到 SPY；先将美元 ETF 序列换算为人民币，再计算同起止日期的日收益差。场内 ETF 的交易价格仅用于行情展示和溢价率，不得作为跟踪误差输入。领域结果继续保留比较对象、口径、共同观测日和截止日期等来源元数据；候选表格中的年化跟踪误差只显示百分比，每只基金数值的提示分别说明其比较对象、共同样本数和截止日期，表格下方只说明统一公式，不向普通用户展示内部“免费代理口径”标签。

所有调用设置短超时、重试上限、并发限制和熔断。生产部署固定依赖版本，并通过契约测试覆盖 JSONP 包装、数组字段位置、空值、单位和上游字段变化。QDII 数据采集与助手属于内建常开能力，不再提供关闭它们的功能开关；AKTools 不映射宿主机端口，但连接独立出站网络访问公开上游。参考项目中的页面回退、交叉校验与历史快照策略必须由本项目独立实现，每一次降级都保留实际来源和置信状态。

**替代方案：**Go API 直接调用未文档化网页接口。该方案镜像更小，但会把网页字段变化扩散到业务服务，且无法复用 AKShare 已维护的解析逻辑，因此不采用。

### 3. 快照优先、请求不直连上游

定时任务刷新基金目录、申赎状态、限额、净值、指数与汇率，业务请求只读取最近一次成功快照。每条快照保存：

- `provider`、`source_url`、`observed_at`、`fetched_at`
- `status`: `fresh`、`stale`、`unavailable`
- `raw_hash` 与规范化后的值
- `error_code`，不保存含凭据的上游错误正文

陈旧阈值按数据类型配置。超阈值数据可以显示，但 MUST 明确标记“数据可能已过期”；从未成功的数据用 `--`。

跟踪误差属于派生数据：采集器在基金累计净值、QQQ/SPY 和 USD/CNY 刷新完成后计算一次，并把数值、共同观测日、截止日期、比较对象和代理口径写入独立的小型 `tracking_error_proxy` 快照。打开助手优先读取该派生快照，不重复加载全年历史序列计算；源序列更新后由下一次刷新生成新派生快照。单机与 TrueNAS 部署不因此新增 Redis；多实例高并发部署可在将来把 Redis 作为二级缓存，但 Redis 不得成为结果的唯一持久载体。

为降低免费上游的突发请求压力，跟踪误差所需的少量累计净值必须先于全市场 ETF 行情批量刷新完成；同一基金代码和基准的重复历史配置在一次刷新中只保留首个成功结果。
累计净值端点发生短暂的传输错误、服务错误或必需数据空响应时，采集器使用短退避重试；首轮耗尽后仅对失败基金执行一次延后补采并记录最终原因。其重试预算高于批量市场接口，最终耗尽后仍按缺失数据处理，不复用价格结果。明确允许空结果的接口不因空数组改变语义。

### 4. QDII 候选采用“场外多选 + 场内单选”

助手只返回映射到同一 `benchmark_id` 的基金。场外基金按“可申购、限额已知、费率、跟踪误差、数据新鲜度”排序，不硬编码固定数量；默认首屏展示多只并允许多选，汇总所选基金的预计可投容量并计算需由场内承接的剩余缺口。场内 ETF 返回多只 IOPV 可用的精确映射候选，按溢折率绝对值和数据完整度排序，用户最多单选一只；没有满足条件的 ETF 时不显示场内区域。

暂停申购的场外基金保留在表格中用于说明真实状态，但不外推为整月暂停；恢复安排未知时月度容量为 `--`。暂停或明确未代销候选禁止新增勾选，但历史已选项允许取消，“全选”排除两者。ETF 面向用户展示的溢价率统一按 `(最新价格 / IOPV - 1)` 计算；上游若提供的是“折价率”，不得直接沿用其相反符号。

渠道限额在领域模型和快照中保留具体销售渠道与来源。普通用户界面的候选行不展示“天天基金”等渠道名，而在表格下方统一说明限额属于公开销售渠道观察值、仅供参考并以实际销售平台为准，避免把单一渠道值误解为全市场统一限额。管理员或用户可以配置自己的渠道限额覆盖，覆盖值与外部值同时保留来源。

基金份额类别只在数据源给出明确类别时追加到基金代码后；空值或 `unknown` 属于缺失元数据，界面直接省略类别，不显示“unknown 类”。

### 5. 跟踪误差只在精确、足量的共同序列上计算

计算统一采用最近一年共同观测日收益差的样本标准差，再乘 `sqrt(252)` 年化。日收益差是计算样本，输出是整个最近一年观察窗口的年化整体误差，不是单日误差，也不是首尾一年收益率之差。场内 ETF 表格将列标题明确写为“近一年年化跟踪误差”。系统优先采用基金复权净值与精确同口径总回报基准；严格口径不可用时，允许采用明确标记的免费代理口径：基金累计净值对比经每日 USD/CNY 中间价换算为人民币的 QQQ/SPY 前复权收盘序列。只有满足以下条件才计算：

- 基金与基准为精确映射；
- 收益口径属于已验证的严格组合或免费代理组合，禁止混搭；
- 对齐后至少有 120 个共同观测日；
- 最新共同观测日未超过配置的陈旧阈值。

`fund_open_fund_info_em` 的累计净值不得冒充复权净值，只能参与上述显式代理组合。未配置 Tushare 时自动尝试免费代理组合；若基金累计净值、QQQ/SPY 前复权行情、每日 USD/CNY、样本数或新鲜度任一不足，跟踪误差显示 `--` 并提供简短原因。不得用波动率、夏普比率或最大回撤冒充跟踪误差。

### 6. 换汇需求由现有月度建议派生，币种集合动态生成

服务端先按现有规则计算预测窗口内每月人民币建议投入，再只选择：

- `direct_us` 且 `fx_quota_relevant=true` → USD
- `direct_hk` 且 `fx_quota_relevant=true` → HKD

`qdii`、`stock_connect`、`local` 均排除。结果的币种集合由符合条件的数据决定：没有港股直投就完全省略 HKD，没有美股直投就完全省略 USD；集合为空时不渲染入口。

外币需求使用对应月份可用的规划汇率换算。未来月份默认使用当前最新中间价作为静态规划假设，并清晰标记“估算”；用户可输入规划汇率做情景覆盖。任何币种缺少汇率时，其外币金额和累计 USD 等值需求显示 `--`，人民币月度需求仍可展示。

采集器优先使用部署方配置并审查过的中国外汇交易中心端点；端点未配置、返回空结果或请求失败时，通过同一内网 AKTools 服务调用 `currency_boc_safe`，选择同时具有正数 USD/HKD 的最新日期，将人民币/100 外币归一化为人民币/单位外币，并把国家外汇管理局页面作为可追溯来源。此降级属于默认本地部署的数据路径，不依赖 Tushare token。

启动刷新分为两个阶段：先并行完成 QDII 申购与 FX 快照，再执行耗时更长的基金/ETF 历史序列刷新。历史上游缓慢或失败不得占满并发槽并延迟两个助手的首屏关键数据。

### 7. 海外标的是动态视觉组，入口属于组而非单行

月度记录页按计划已有顺序渲染标的。连续或经布局归集后的海外直投标的放入同一个视觉容器，组头按真实市场显示美股/港股标的数量，组底显示海外直投总数，并在右下角显示“年度换汇预测”入口。入口由真实直投标的决定，不依赖汇率快照是否成功；数据缺失时侧栏显示 `--`。QDII 行仍保留自己的基金助手入口。参考图 `assets/fx-forecast-layout-reference.png` 只用于说明分组和组级按钮位置，图内多余示例行不构成数据或数量要求。

### 8. QDII 确认方案按月持久化

QDII 助手的勾选不是纯展示过滤，而是用户针对某个计划月份和 QDII 标的确认的执行方案。服务端以月度记录和标的为唯一键保存场外基金代码集合、每只场外基金在确认时的每日投入与本月合计、最多一只场内 ETF 代码、该 ETF 在确认时对应的场内合计及确认时间；场外每日投入取确认时的有效单日限额，本月合计取确认时的可执行容量，场内合计由服务端按当月该标的剩余建议需求减去所选场外基金可执行容量计算，客户端不得自行指定。任一金额所需数据未知时该金额保持未知，旧确认记录不做推测回填。再次打开同月同标的助手时回显该方案。月度记录页通过轻量确认摘要读取基金主数据名称、代码和全部持久化金额，并在对应 QDII 行的助手入口下方以分区卡片展示本月已选方案，无需加载行情或先打开侧栏。其他月份不继承“已确认”状态，以免把随限额和市场状态变化的旧方案误认为本月决定。保存时重新校验基金仍属于同一生效精确基准映射，暂停申购的场外基金不得新确认。

QDII 场外发现必须先以 `fund_open_fund_rank_em(symbol="QDII")` 限定真实 QDII 开放式基金目录，再与全市场 `fund_purchase_em` 按代码连接。新候选经基金概况精确验证并写入映射后，采集器在同一次刷新内直接写入其申购快照，不得用刚持久化的毫秒时间戳重新查询活跃映射，否则 MySQL 时间精度差异会让首次刷新遗漏数据。

每次申购刷新先为全部已有精确映射写入最新状态和限额，再串行验证尚未映射的新候选；已有映射不要求基金当天仍出现在 QDII 排名目录中，因为排名目录可能临时省略限购、暂停或缺少当日收益的基金。候选发现的数量和基金概况接口耗时不得阻塞已有用户候选的快照更新。

年度换汇预测默认启用。部署方仍可通过显式配置关闭，但官方 Compose 与 TrueNAS 模板不得默认关闭；即使没有汇率快照，服务端仍返回由权威月度建议派生的人民币需求。

## Risks / Trade-offs

### 数据真实性校验补充

- 批量申购状态保留原文；“限大额”“暂停大额申购”为限额申购，不等于全面暂停。零值、缺失或低于起购额的限额均不可参与容量计算。
- 对已映射的异常限额行，采集器以 5 秒单次超时、30 秒总预算查询同基金东方财富费率详情页，严格核对页面基金代码；未开通代销单独标记，页面不可用时保留未知值。详情核验在已有候选批量快照写入之后、新候选发现之前执行，不阻断业务请求。
- 月度容量仅使用当前计划月的新鲜状态与有效正数限额；剩余周一至周五仅为工作日估算，未扣除基金假期、临时暂停或当日截止时间，不宣称为真实开放日历。
- 场外跟踪收益样本必须同时匹配起始和结束日期，拒绝多日/单日错配。计算窗口及 30 天前置样本拒绝重复、未来日期以及非正/非有限数值；多年以前不参与计算的加减法复权负价不阻断最近一年。派生缓存带算法版本，并校验样本数、基准和实际截止日期。
- FX 缺少基线时年度汇总保持未知，不把空聚合变为零；汇率新鲜度同时检查观测日期和抓取时间。

- [公开网页接口可能变更或限流] → 固定 AKTools/AKShare 版本、使用快照与契约测试、熔断降级，不阻断核心流程。
- [开源代码许可与公开数据授权被混为一谈] → 分别记录代码许可证和上游数据生产使用结论；无许可证参考仓库不得复制代码，未获数据授权的提供方不得在生产启用。
- [渠道限额频繁变化且 A/C 份额不同] → 以基金代码和渠道为最小粒度，显示时间戳，不跨份额复用。
- [指数收益口径与基金净值口径不一致] → 精确记录价格/总回报口径，不兼容时不计算跟踪误差。
- [中间价与银行实际成交价有偏差] → 标记为规划参考，支持用户情景汇率，不承诺成交结果。

## Migration Plan

1. 先迁移标的市场档案与基金/基准映射；无法确定的现有标的保持 `unknown`，不启用对应助手。
2. 部署仅内网可访问的市场数据服务和快照表，先以只读观测模式刷新并检查数据质量。
3. 启用后端领域 API，验证上游关闭时月度记录仍可正常加载和保存。
4. QDII 助手与数据刷新随应用常开；海外分组和换汇侧栏按真实计划标的渲染。
5. 回滚时可停止外部刷新任务并继续读取已有快照；保留市场档案和快照表，不影响原有计划数据。
