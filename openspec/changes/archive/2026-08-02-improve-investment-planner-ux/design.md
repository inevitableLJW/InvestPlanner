## Context

前端是 React 19 + TypeScript + Vite 的单页应用，当前计划设置与月度录入集中在 `PlanPage.tsx`，后端以 destination 字段和基点数保存标的配置。现有 API 已能校验比例合计和计算金额，因此本次以兼容 API 的前端体验重构为主，同时保留服务端作为最终校验者。

## Goals / Non-Goals

**Goals:**

- 用一致的“投资标的”术语、常用预设和渐进式自定义入口降低配置成本。
- 让比例配置通过离散下拉、自动补足和均分操作快速达到 100%，并始终显示剩余量与保存状态。
- 用本地图标和明确的信息层级提升支出来源辨识度与月度录入效率。
- 建立可复用的视觉 token、图标组件和轻量动效，同时兼顾移动端、键盘操作和减少动态效果偏好。
- 保持现有 API、数据库和历史快照兼容。

**Non-Goals:**

- 不修改投资建议计算公式、取整策略或历史快照语义。
- 不引入证券行情、交易下单或真实 App 账号连接。
- 不在本次新增支出来源管理后台或改变服务端 destination 命名。

## Decisions

### 使用前端配置表驱动常用投资标的和支出图标

常用标的将由有序常量维护，选择器提供这些预设以及“自定义标的”。支出来源通过规范化后的名称映射到内联 SVG 图标、品牌色和短标签，未知名称使用钱包回退图标。这样无需远程 CDN、图片许可或新增后端字段，也能让已有数据立即获得视觉增强。备选方案是保存 icon URL 或引入整套图标库，但前者需要迁移且存在失效风险，后者无法完整覆盖国内 App 品牌。

### 仍以基点数为状态，UI 只提供离散百分比

比例下拉提供 0、5、10、15、20、25、30、35、40、45、50、60、70、75、80、90、100 百分比选项，内部继续保存为基点数。修改某一启用标的后，用户可以明确点击“补足剩余”把差额赋给该项，或点击“智能均分”在所有启用项之间分配整百分比并把余数稳定分配给靠前项。相比自动静默改写其他项，这种显式联动更可预期，也不会让用户刚选的值被意外覆盖。

### 对 active 草稿执行前端硬校验

启用中的计划只有在至少一个标的启用、名称不重复且合计为 100% 时才能提交；草稿仍可保存未完成配置，方便分步编辑。实时进度条和剩余提示在提交前暴露问题，服务端继续执行权威校验。

### 采用蓝色 CSS token 和渐进式动效，不增加运行时 UI 依赖

现有界面规模较小，重构为卡片、分段控制、状态摘要、输入前缀和响应式网格即可达到目标。使用蓝色主色、浅蓝语义背景和深蓝渐变强调卡片的 CSS 变量统一色彩、圆角、阴影与间距，并用 `prefers-reduced-motion` 关闭非必要动画。相比引入大型组件库，这能避免 bundle、主题覆盖和迁移成本；后续仍可按同一 token 接入无样式组件库。

### 把复杂配置拆成可扫描区块

设置页按“基本设置 → 投资规则 → 标的配置 → 保存状态”组织；月度页按“月份和收入 → 支出 App → 实时摘要 → 计算结果”组织。主动作保持唯一且在桌面端吸底，次要操作使用弱按钮，错误与成功反馈紧邻对应区块。

### 使用确定路径与显式确认完成设置流程

计划内 Tab 使用以计划 ID 为基础的绝对路径，避免嵌套路由在不同页面层级解析相对地址时跳转错误。设置保存成功后展示模态确认层；用户确认后回到该计划概览，使“保存完成”的下一步明确可见。标的排序保持 `sortOrder` 与数组顺序一致，既支持按启用标的比例从高到低排序，也支持拖拽和现有的键盘上/下移动按钮。

### 用应用壳层 token 实现可持久化皮肤

皮肤选择器放在全局壳层，选择结果写入浏览器本地存储，并通过壳层的 `data-skin` 覆盖 CSS token。这样所有页面立刻继承同一配色，无需给每个组件传递主题参数；默认保持海洋蓝，并提供暮光紫和青绿两种轻量皮肤。

亮色与暗色模式独立于皮肤保存为 `data-mode`，让用户能在任意配色下选择阅读环境。皮肤选择器使用可访问的自定义列表框而非原生 `select`，以确保每个皮肤名称旁都能稳定显示对应颜色块。

## Risks / Trade-offs

- [App 图标是本地抽象图形而非官方资源] → 使用品牌色、文字标识和稳定 SVG 组合提高辨识度，并为未知来源提供一致回退。
- [离散比例无法表达任意小数] → 当前业务常用配置以整数比例为主，后端仍保持基点精度和兼容已有小数数据；已有非标准值会作为当前值显示在下拉中。
- [智能均分可能不是用户最终偏好] → 只在用户点击时执行，并保留逐项下拉和补足剩余入口。
- [单文件页面继续增长] → 把标的配置、来源图标和图标基础组件拆到独立模块，页面只保留流程状态与 API 调用。

## Migration Plan

1. 新增纯前端标的预设与图标组件，随后替换设置和月度录入 UI。
2. 保持所有请求字段与响应类型不变，对既有自定义名称和非标准比例做兼容显示。
3. 运行前端单元测试、lint 和 production build，再运行服务端测试确认契约未受影响。
4. 如需回滚，仅回退前端组件和样式；数据库不需要回滚或迁移。
