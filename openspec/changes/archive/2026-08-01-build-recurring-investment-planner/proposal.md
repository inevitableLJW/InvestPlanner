## Why

每月根据实际收入和分散在不同付款平台的支出手工计算可定投资金，容易遗漏、重复或无法持续复盘。需要一个以“定投计划”为中心的 Web 应用，让用户先定义计划及资金目的地，再在该计划内持续录入月度收支、生成分配方案并统计实际投入。

## What Changes

- 新增用户名密码注册、登录、退出和会话管理；所有计划及其月度数据均按用户隔离。
- 新增定投计划创建和管理；用户先创建计划，再进入计划详情录入收入、支出、计算结果和实际投入。
- 每个新计划默认提供支付宝基金、A股、港美股、现金四个定投目的地，但默认项仅作为模板；用户可以新增、重命名、排序和停用目的地，也不必启用全部默认项。
- 每个计划可设置默认定投比例、预留资金、金额取整规则，以及当前启用目的地的分配比例；至少启用一个目的地，启用项比例合计为 100%。
- 在具体计划中按月份录入总收入和按微信、支付宝、美团、抖音、银行卡、交通等付款平台或账单来源汇总的支出，并支持自定义支出来源。
- 在具体计划中选择或自定义当月定投比例，计算建议定投总额，并分配至该计划当时启用的任意数量目的地。
- 按计划和目的地登记实际投入，展示月度趋势、累计投入、目的地占比和计划完成率。
- 第一版采用 React 前端、Gin 后端、GORM 数据访问和 MySQL 持久化；不包含第三方登录、密码找回、角色权限、账单导入、消费用途分类、证券持仓、净值、收益率、自动交易或汇率换算。

## Capabilities

### New Capabilities

- \`investment-plan-management\`: 提供账号注册登录、用户数据隔离、多计划管理，以及每个计划的默认参数和可配置定投目的地。
- \`monthly-cashflow-entry\`: 在选定计划中按月份录入总收入和按付款平台或账单来源汇总的支出，并维护可复用的支出来源。
- \`investment-allocation-calculation\`: 在选定计划中计算可定投基数和建议总额，并按任意数量启用目的地的比例完成确定性分配。
- \`contribution-tracking\`: 按计划和目的地登记实际投入、维护执行状态，并汇总月度与累计投入统计。

### Modified Capabilities

无。

## Impact

- 新增 React Web 前端、Gin REST API、GORM 数据访问层、MySQL 数据库模型，以及后端权威计算逻辑。
- 新增计划列表/创建、计划详情、目的地设置、计划内月度计算、计划内投入历史和统计页面。
- 数据关系从“用户直接拥有一份月度数据”调整为“用户拥有多个计划，计划拥有目的地和月度数据”；月份唯一性按计划计算。
- 新增用户、会话和所有业务数据的用户归属关系；生产部署需要 HTTPS、会话 Cookie 和数据库配置。
- 当前仓库没有既有业务规格或应用代码，因此没有需要迁移的 API、数据库数据或现有功能。
